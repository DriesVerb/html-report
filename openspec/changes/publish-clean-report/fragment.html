Problem & Vision

Reports are iteratively authored using the bottom-dock editor and agent bridge. Once editing is finalized, stakeholders and public audiences need a clean, uncluttered deliverable without developer tools, gear menus, or prompt editors. Offering a deterministic publish flow guarantees that exported reports are completely self-contained, pristine, and byte-reproducible across identical builds.

Goals

  • Provide a clear 'Set as Published' toggle and 'Download Clean HTML' action in the Settings panel.
  • Produce a deterministic standalone HTML download that cleanly omits the gear icon (#settings-dropdown), bottom edit dock (#edit-dock), and authoring chrome.
  • Ensure zero authoring script footprint or residual task draft queues in the published bundle.
  • Support a deterministic CLI/build flag (--published in build-report.mjs) to generate clean, gear-free reports in headless pipelines.
  • Guarantee deterministic serialization: no timestamps, no non-deterministic session tokens, completely reproducible byte-for-byte.

Non-goals

  • Does not delete draft tasks from the author's local browser storage (keeps drafts safe for future edits on the development page).
  • Does not alter reader features (charts, Mermaid diagrams, TOC, print stylesheets, and tables remain 100% interactive).

Design

Publishing Toggle & Action

In Settings panel -> Export & Publishing section: add 'Publish State' toggle and 'Download Published (Clean HTML)' button. When marked as published, the active report sets <meta name="html-report-published" content="true"> and offers the clean download.

Deterministic DOM Tree Stripping

In buildInlinedHtmlSnapshot({ mode: 'published' }), clone the DOM tree, prune #settings-dropdown, remove #edit-dock, strip authoring modals/toolbars, strip data-agent-authoring attributes, and omit draft task queues. Output is serialized with sorted attributes and standardized whitespace.

Deterministic Output Guarantee

Zero non-deterministic IDs (e.g. _sessionId or random math tokens), zero generation timestamps, and normalized whitespace so hashing identical input HTML yields identical output checksums.

CLI Pipeline Parity

build-report.mjs --published applies the same DOM pruning template transform at build time, omitting the gear icon and editor from the start.

Standalone Viewer Preservation

The published HTML retains responsive layout, Table of Contents dropdown (TOC stays in navbar or standalone header), offline scripts, Grid.js, Chart.js, Mermaid, and print CSS.

Requirements

Set as Published Toggle
The system SHALL provide a 'Publish' control in the Settings panel allowing authors to mark the report as published.
Deterministic Clean Download
The system SHALL offer a download action that yields a standalone HTML file completely stripped of the gear icon, the edit prompt editor dock, and all authoring controls.
Deterministic Serialization
The clean download generation MUST be deterministic, producing identical byte output for identical document content without timestamps or random tokens.
CLI Published Flag
The build pipeline build-report.mjs SHALL support a --published flag to emit the clean gear-free report directly.
Preservation of Reader Features
The published report MUST preserve core viewer capabilities: responsive reading, Table of Contents, interactive charts, Mermaid diagrams, and print styles.
