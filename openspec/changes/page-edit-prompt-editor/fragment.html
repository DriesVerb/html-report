Problem & Vision

Reviewing a report produces a stream of small change requests (fix this chart, reword that heading). Today they live in your head or a chat. A per-page task queue lets you capture them in place while reading, rank them, and hand the agent one clean, reproducible prompt. Everything is deterministic and baked into every html-report, so no LLM is needed to build the prompt.

Goals

  • Gear → Edit opens a compact editor docked to the bottom edge of the screen.
  • Create tasks (title + content), list them in a Queue tab, prioritize them, mark them done.
  • Generate a deterministic prompt from the queue; copy it, or send it straight to the agent when the page is AI-capable and connected.
  • Scroll-following: the dock stays put while you read and shows which section you are in, so tasks attach to what you see.
  • AI-capable but offline: surface the turnkey reconnect flow instead of a dead button.

Non-goals

  • No server-side persistence of tasks in v1 (localStorage per page).
  • No multi-user collaboration or sync.
  • The prompt is not LLM-generated; it is a pure template function.

Design

Dock UI

#edit-dock is position: fixed; bottom: 0, full-width capped at max-w-3xl centered. Collapsed: 40px bar (task-count badge, current-section chip, + button). Expanded: max-h: min(38vh, 320px), internal scroll. body gets padding-bottom equal to the dock height via ResizeObserver so content is never covered. print:hidden, z-index below modals, above content.

Tabs

Compose: title input, content textarea (auto-grow to 4 lines), priority select, optional section anchor chip (defaults to the current section), Add (Ctrl/Cmd+Enter). Queue: sortable list with P1/P2/P3 chips, up/down + drag reorder, done checkbox, delete, click to scroll to anchor. Footer: Generate prompt.

Scroll-following

An IntersectionObserver over headings and section[id] tracks the section nearest the viewport top and writes it to the dock chip. New tasks anchor to it. In the Queue tab, tasks anchored to the visible section are highlighted, and clicking a task smooth-scrolls to its anchor and flashes an outline. This gives the better overview of what needs editing.

Data model

Task { id, title, content, priority: 1|2|3, order, done, anchor: { id, label } | null }. Stored in localStorage key html_report_edit_queue:<pageKey>; pageKey = <meta name="html-report-source"> (emitted by build-report) else location.pathname.

Deterministic prompt

Pure function buildEditPrompt(tasks, page) in the runtime, unit-testable in Node. Order: priority asc, then manual order; done tasks excluded. Output is byte-identical for identical input (no timestamps, no randomness). Sections: page identity (title, source path, report mode), numbered tasks with priority and anchor, standing constraints (preserve html-report conventions, edit the source fragment, rebuild with build-report.mjs, keep localhost:3000 live, update tasks if OpenSpec).

Send to agent

States: AI-capable + connected → primary button *Send to agent* posts the prompt to a new dev-server endpoint POST /__agent_edit__ (localhost only, scoped to the served file) and streams status; hot-swap live reload shows the result. AI-capable + disconnected → button becomes *Turnkey reconnect* opening the existing reconnect modal with the edit prompt included. Not AI-capable → *Copy prompt* only, with a link to Settings → Activate AI (Story 2).

Requirements

Bottom-docked editor
The editor sits at the bottom edge, stays compact (collapsed 40px, expanded max 38vh), and never covers page content.
Task CRUD with priority
Users can create tasks with title and content, edit/delete them, mark done, and set/reorder priority.
Queue tab overview
A tab lists all tasks ordered by priority with counts, and supports reprioritizing.
Scroll-following context
The dock shows the section currently in view, anchors new tasks to it, and jumps to a task's anchor on click.
Deterministic prompt
Generating a prompt from identical tasks always yields identical text; done tasks are excluded; order follows priority.
Agent hand-off states
Connected+AI sends to the agent; AI-capable but disconnected offers the turnkey reconnect; otherwise copy-only.
Persistence
Tasks survive reloads per page and never leak between pages.
