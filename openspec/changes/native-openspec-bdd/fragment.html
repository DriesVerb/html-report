We are implementing the feature `<feature-name>` using OpenSpec and our zero-framework BDD-as-TDD workflow.

Follow these strict constraints:
1. Zero External Frameworks:
   - Do not install Cucumber or third-party test runners.
   - Use our native Node.js test harness: `node:test`, `node:assert/strict`, `tests/harness/bdd.mjs`, and `tests/harness/openspec-bdd.mjs`.

2. Double-Loop BDD-as-TDD Workflow:
   - Step 1 (Outer Loop - Red Scenario Gate):
     Read the scenarios in `openspec/specs/<feature-name>/spec.md` (or the change delta spec) and create `tests/<feature-name>.bdd.test.mjs`.
     Bind the Given-When-Then scenarios using `bindOpenSpec()`. Run `node --test tests/<feature-name>.bdd.test.mjs` to verify scenarios show as `todo` or failing.
   - Step 2 (Inner Loop - Unit TDD):
     Write focused unit tests in `tests/<feature-name>.test.mjs` for low-level algorithms, edge cases, and helper functions. Implement minimal code to turn them green.
   - Step 3 (Outer Loop - Green Scenario Gate):
     Implement the scenario steps in `tests/<feature-name>.bdd.test.mjs` until all BDD acceptance scenarios pass.

3. Repository Verification Gate:
   - Execute the complete test suite: `node --test tests/*.test.mjs`.
   - Ensure zero regressions against all existing test suites.
   - Update `tasks.md` checklist and the companion `index.html` to reflect live journey progress.
   - Ensure `http://localhost:3000` reflects the updated journey dashboard.
