The Progressive Complexity Principle

Ensuring direct skill usage remains lightweight and untouched, activating advanced machinery strictly for external callers.

MODE 1: STANDALONE (SELF)
Zero Added Complexity

When invoked by a developer or direct user prompt without --caller:

  • Zero Vault Touches: .caller-requests/ is never read, created, or modified.
  • Zero Profile Overhead: Bypasses profile lookup, schema validation, and pruning logic.
  • Predictable Outputs: Generates standard ./report.html with default light theme.
node harness.mjs run fragment.html
MODE 2: CALLER-AWARE (EXTERNAL)
Rich Contextual Rendering Bus

When invoked by external agent skills, subagents, or automated pipelines with --caller <id>:

  • Profile Resolution: Automatically loads or scaffolds .caller-requests/profiles/<caller>.md.
  • Vault Ephemeral Runs: Persists run.json & trace.json and prunes to last 10 runs.
  • Contextual Routing: Emits ./report-<caller>.html in caller's CWD.
node harness.mjs run fragment.html --caller memory-leak-debugging

Performance & Startup Benchmarks

Comparing standalone execution, caller-aware execution, and legacy multi-step workflows.

Sub-2ms Standalone Startup

When called standalone, zero filesystem lookups for profiles or vault directories are executed. Pure in-memory AST and regex linting runs instantaneously.

Zero Git Clutter

Standalone runs produce only the designated output HTML file. When external callers run, all profiles and ephemeral logs remain securely quarantined in .caller-requests/.

Bounded Hallucination Ceiling

Both modes enforce a strict 3-attempt remediation ceiling with spoon-fed prescriptive instructions, preventing runaway loops.
