Queue Re-Editing, Styling Studio & Reset Architecture

The runtime reuses existing HTMLReportEdit.updateTask() and the zero-dependency OKLCH engine (compileTheme(), registerCustomTheme(), setReportTheme()) already bundled in report-runtime.js, adding POST /__agent_style__ in serve-report.mjs for persistent document defaults.

Key Architectural Decisions & Scope

1. Queue-to-Compose Re-Editing

  • Clicking a task row or its explicit ✎ button invokes editTaskInCompose(id), loading title, content, priority, target, and anchor into Compose.
  • Dedicated clickable section anchor chip (§ label) preserves one-click scrollToAnchor() without blocking row click-to-edit.
  • Compose switches to Save + Cancel, updates in place via updateTask(), invalidates stale prompts, and clears cleanly on + Task or delete.

2. Styling Studio & Document Default

  • Styling button (#edit-tab-styling) sits on the right side opposite Compose | Queue.
  • Lets users pick any of the 32 DaisyUI themes or custom themes and click Set as Default (persisted via POST /__agent_style__ or local fallback).
  • Compact OKLCH Style Editor edits theme name, extends base, 5 semantic colors, and border radius live across DOM, Chart.js, and Mermaid.

3. Full Reset Button Next to Styling

  • Reset button (#edit-dock-reset-btn) sits directly next to Styling on the right side of the header row.
  • Confirmation-guarded resetAll() clears page tasks, Compose draft/edit session, target selection, auto-priority, and generated prompt.
  • Clears localStorage custom theme overrides and resets active/document default theme back to light (customTheme: null).
