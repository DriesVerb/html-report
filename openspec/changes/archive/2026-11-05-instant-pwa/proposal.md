# Proposal: Instant Progressive Web App (PWA) Generation for HTML Reports

> Visual Plan & Companion Dashboard: [index.html](file:///home/eta/projects/html-report/openspec/changes/instant-pwa/index.html) | Servable at `http://localhost:3000`

## Why

Reports generated by `html-report` are already publication-grade, responsive, and rich with data visualizations, dashboards, and interactive widgets. However, users frequently need these reports on the go—on tablets, mobile devices, and field workstations—often in environments with intermittent, air-gapped, or zero internet connectivity.

Currently, saving a report as a standalone web app requires manually crafting a Web App Manifest (`manifest.webmanifest`), configuring multi-size icons, authoring a custom Service Worker (`sw.js`) with appropriate cache strategies, wiring `beforeinstallprompt` browser hooks, and maintaining offline fallback states.

When a user or developer asks:
> *"I want to create a PWA from this report"*

The `html-report` skill / html-helper should natively and instantly fulfill that request with **zero friction, zero external dependencies, and complete offline capability**.

## What Changes

1. **Instant PWA Generation Engine (`skills/html-report/scripts/pwa-builder.mjs`)**:
   - Zero-dependency generator for W3C Web App Manifests (`manifest.webmanifest`), Service Worker runtime (`sw.js`), and responsive SVG / PNG app icons.
   - Dual caching strategy: Stale-While-Revalidate / Network-First for HTML navigation; aggressive Cache-First for static CDN scripts, DaisyUI stylesheets, and visual assets.

2. **Any-Report Converter CLI (`skills/html-report/scripts/generate-pwa.mjs`)**:
   - Dedicated standalone CLI tool that takes *any* existing HTML report file (`node skills/html-report/scripts/generate-pwa.mjs ./my-report.html`) and instantly produces an installable PWA with companion manifest, service worker, and icons.

3. **Deterministic CLI Flag & Mode Integration (`--pwa` & `--mode pwa`)**:
   - Integrated into [`build-report.mjs`](file:///home/eta/projects/html-report/skills/html-report/scripts/build-report.mjs) and [`harness.mjs`](file:///home/eta/projects/html-report/skills/html-report/scripts/harness.mjs).
   - Added canonical mode `"pwa"` and flag `--pwa` with automatic asset emission and `<head>` link/meta tag injection.

4. **In-Report PWA Runtime & Install Affordances**:
   - Dynamic **Install App** button in the DaisyUI navbar (utilizing native `beforeinstallprompt`) and in the Download dropdown.
   - Live **Offline Status Badge** in the header reflecting `navigator.onLine` state.
   - Reactive **Theme-Color Synchronization**: dynamically updates `<meta name="theme-color">` to match whichever of the 32 DaisyUI themes the user selects.

5. **PWA-Aware Dev Server Serving (`serve-report.mjs`)**:
   - First-class support for `.webmanifest` (`application/manifest+json`) and `sw.js` with `Service-Worker-Allowed: /` headers.

6. **Agent Skill Capability & Documentation**:
   - Updated [`SKILL.md`](file:///home/eta/projects/html-report/skills/html-report/SKILL.md) to explicitly guide agents when asked *"I want to create a PWA"*.
   - Dedicated comprehensive reference guide: [`references/instant-pwa-guide.md`](file:///home/eta/projects/html-report/skills/html-report/references/instant-pwa-guide.md).

## Capabilities

### New Capabilities
- `instant-pwa`: End-to-end instant Progressive Web App generation, manifest authoring, service worker caching, theme-color reactivity, install prompt management, and offline operation for any HTML report.

### Modified Capabilities
- `deterministic-assembly`: Extended `build-report.mjs` to support `--pwa` and `--mode pwa` flags with companion asset output.
- `report-rendering-modes`: Added `pwa` canonical rendering mode with dev server policy.
