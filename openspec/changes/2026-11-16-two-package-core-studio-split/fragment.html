Two-Package Architecture & Inverted Clean Runtime

One Repo · Two Workspaces

Current Bottlenecks Observed

  • Bake-then-strip chrome: Edit dock & modals ship in every report and require 3 overlapping strippers (--published, publish-report.mjs, HTMLReportPublisher).
  • Studio coupling in compiler: build-report.mjs checks for root create.html to mirror projects/.
  • Monoliths & root sprawl: 6,414-line report-runtime.js, 4,663-line serve-report.mjs, duplicated 4,434-line create.html, leftover tmp-pwa-bdd/.
  • Offline test fragility: 21/613 tests fail offline (mostly Playwright CDN fetches + a few non-CDN regressions).

Plan A Target State

  • Clean-by-default output: packages/core emits viewer-only HTML; packages/studio injects Edit Mode & AI Bridge via opt-in --editable / server slots.
  • Strict export boundary: @html-report/studio imports @html-report/core solely through public subpath exports (enforced by boundary test).
  • Modular server & zero duplication: serve-report.mjs split into 6 route modules; single canonical create.html.
  • Skill compatibility preserved: Root package.json exports and skills/html-* facades stay intact.
