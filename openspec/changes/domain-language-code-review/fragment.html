Core Review Areas & Additional Alignment Opportunities

Concrete gaps where aligning code with the domain language eliminates drift.

Core 4 Review Areas

Phase 1 & 2
  • 1. Assembly vs. Pipeline: Separate mechanical join (<100ms) from FSM pre-flight normalizers in build-report.mjs and harness.mjs.
  • 2. Edit Mode vs. Published Document: Standardize authoring markers in template-shell.html and report-runtime.js; verify stripAuthoringMarkup() leaves only clean viewer tools.
  • 3. User-Facing vs. Agent-Facing: Surface Beneficiary & 2-Axis selectors in create.html (Human GUI); keep CLI tools headless, JSON-friendly, and token-efficient.
  • 4. Two-Axis Decoupling: Verify Static File builds run client-side fetch() (PokéAPI/Weather) cleanly without server hooks; scope Datastar SSE to Server-Connected mode.

Additional Alignment Opportunities

Phase 3
  • 5. PWA as Packaging Modifier: Clarify across pwa-builder.mjs and skills/html-pwa/SKILL.md that PWA (--pwa) wraps any Interactive Archetype rather than competing with content archetypes.
  • 6. Skill Router & Facades: Tag each skills/*/SKILL.md and skill-router.mjs entry with its Beneficiary, Serving Mode, and Behavioral Mode (keeping <5KB limits).
  • 7. MCP Tool Schemas: Align mcp-server.mjs (NATIVE_MCP_TOOLS) descriptions with canonical terms (SemanticFragment, OutputDeliverable, PublishedDocument).
  • 8. Docs & Guides: Harmonize README.md, docs/architecture-fsm.md, api-and-cli-reference.md, and live-telemetry.md with the Ubiquitous Glossary.
  • 9. Automated Domain Linter: Add test assertions scanning CLI --help strings and MCP schemas for deprecated synonyms.
