In-Depth Architecture Analysis

Detailed technical breakdown, operational characteristics, strengths, and constraints of each option.

1

Option 1: Pure Node.js Standard Library CDN Server

scripts/local-cdn.mjs • zero npm install

You vendor the required libraries (DaisyUI, Tailwind, Chart.js, etc.) once into a local folder. A lightweight 60-line script using Node's native node:http, node:fs, and node:zlib serves them with HTTP caching, ETag validation, and Brotli/Gzip compression.

Execution Blueprint:
# 1. Start the zero-dependency CDN (cold startup <2ms)
node scripts/local-cdn.mjs --port 8080
# 2. Reports reference assets locally:
<script src="http://127.0.0.1:8080/cdn/chart.js"></script>
Key Advantages
  • Tiny HTML Reports: Individual HTML files remain tiny (~30KB–80KB) because they link to shared URLs.
  • Browser Cache Multiplier: If an operator opens 20 different reports, the browser downloads the 16 libraries once; the next 19 load instantaneously from cache.
  • Team/LAN Distribution: Can run on one machine in a private lab and serve assets to all workstations on the subnet.
  • Zero Dependencies: No node_modules, zero supply-chain risk.
Limitations
  • Requires a background process running (e.g. on port 8080).
  • Double-clicking an HTML file without the server running results in unstyled reports.
2

Option 2: Full Inlined Single-File Report

build-report.mjs --inline • zero network

The build script reads the vendor files from disk and injects them directly into <style> and <script> tags inside the generated HTML report. The result is a 100% self-contained document that needs no internet, no server, and no port.

Execution Blueprint:
# 1. Build self-contained artifact in <100ms
node scripts/build-report.mjs --inline --output report.html
# 2. Open anywhere with zero network:
xdg-open report.html # Opens directly via file://
Key Advantages
  • Zero Running Processes: No background Node server, no daemon, no port allocations.
  • Maximum Portability: A single file can be emailed, transferred via USB stick, or archived permanently in compliance vaults.
  • Double-Click Safe: Works over file:/// protocol on any browser without server dependencies.
  • Zero Dependencies: Built entirely with native Node.js string operations.
Limitations
  • Larger HTML file size (~1.5MB–3.5MB depending on which of the 16 CDNs are active).
  • Assets are duplicated in each HTML file rather than shared across reports in browser cache.

1. Public Third-Party CDN Vectors

Relying on external hosts (cdn.jsdelivr.net, cdnjs.com) outsources operational uptime and client trust to third parties.

• Poisoned CDN Edge: If a CDN maintainer account or cache is breached, injected JavaScript executes on the user machine with the report's origin privileges.
• OPSEC / Intelligence Leak: Classified or internal networks leak IP addresses, browser configurations, and document titles via the HTTP Referer header on every asset fetch.
• Essential Mitigation: Enforce Subresource Integrity (SRI) hashes (integrity="sha384-...") on all tags.

2. Fastify & `node_modules` Vectors

Introducing full server frameworks imports dozens of transitive packages into the air-gapped environment.

• Transitive Supply Chain: Packages like fastify, @fastify/static, and @fastify/compress pull in dependency trees subject to periodic prototype pollution and ReDoS CVEs.
• Air-Gapped Maintenance: Security patches cannot be automatically installed via npm audit in disconnected environments, leaving known vulnerabilities unpatched indefinitely.
• Process Escalation: If executed under a privileged account (e.g. root in Docker), framework flaws can compromise the host machine.

3. Option 1: Native Node Server Implementation Risks

Writing a zero-dependency server means you must manually implement the defenses that web frameworks handle automatically.

• Path Traversal Vulnerability: Failure to sanitize incoming URLs can allow attackers to read /etc/passwd or SSH keys via /cdn/../../../../etc/shadow.
• 0.0.0.0 vs 127.0.0.1 Binding: Binding to 0.0.0.0 inadvertently broadcasts the asset server to the entire LAN/Wi-Fi subnet.
• Compression DoS: Unrestricted on-the-fly Brotli/Gzip compression on concurrent streams can exhaust CPU cores without thread isolation.

4. Option 2: Full Inlining & CSP Hardening

Eliminating network ports shifts the entire security boundary to client-side Content Security Policies and browser sandboxes.

• CSP 'unsafe-inline' Dilemma: Inlining scripts into HTML forces the document to declare script-src 'unsafe-inline', opening the door for DOM-based XSS attacks.
• Cryptographic Hash Defense: Inlining scripts with pre-calculated sha256-... hashes restores strict CSP without requiring 'unsafe-inline'.
• file:/// Origin Boundaries: Different browsers treat file:/// paths with varying degrees of origin isolation, requiring verification in locked-down environments.

Production Hardening Checklist for Air-Gapped Environments

Mandatory engineering safeguards before shipping either zero-dependency setup

For Option 1 (Native Node CDN)
  • Enforce Canonical Prefix Guard: Always verify fullPath.startsWith(ASSET_DIR) after path.normalize().
  • Bind to 127.0.0.1 Only: Never default to 0.0.0.0 unless explicit LAN sharing is authorized.
  • Run as Unprivileged User: Execute Node under a sandboxed UID/GID with read-only filesystem permissions on vendor-cdn/.
  • Pre-Compress Assets: Store .br and .gz pre-built files on disk to eliminate live CPU compression overhead.
For Option 2 (Full Inlining)
  • SHA-256 Script Hashes: Automatically inject SHA-256 hashes into <meta http-equiv="Content-Security-Policy"> to block XSS.
  • Pre-Audit Vendored Code: Run automated static analysis (e.g. Semgrep) against vendor JS files before initial bundle inclusion.
  • Memory-Cap Safeguards: Strip redundant map files and comments to keep overall document size under 3MB.
  • Sanitize HTML Dynamic Injectors: Ensure user data fragments passed into the builder are escaped before inlining.

Strategic Recommendation

How to choose the ideal pattern for your specific environment

Choose Option 1 (Native Node CDN) when:
  • You are actively developing locally and running the dev server (localhost:3000).
  • You generate dozens of reports per day and want to keep report files small (~50KB each).
  • You want all reports to share the browser cache for instant loading.
  • You want to serve reports across an internal team subnet or local staging container.
Choose Option 2 (Full Inlining) when:
  • You need to email or deliver the report to external stakeholders or executives.
  • The recipient is on an air-gapped machine and will open it with double-click (file:///).
  • You cannot guarantee background services or ports (like port 8080) are open.
  • The deliverable must remain permanently archived and render identically in 10 years with 0 infrastructure.
